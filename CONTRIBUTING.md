# Участие в переводе

О пропущенной фразе или неверном термине сообщайте через Issues. Укажите версию игры, версию патча, точный текст и экран. Сохранение для обычной ошибки перевода не требуется.

## Файлы

- `src/literals.json` — переводы обычных фраз; ключи нормализованы в нижний регистр.
- `src/templates.json` — пары «английский шаблон → русский шаблон».
- `src/fccd-ru.js` — обработка отображаемого текста.
- `installer/` — установка, откат и документация готового пакета.
- `release-manifest.json` — хеши выпущенной версии и поддерживаемой сборки.
- `packages/` — готовый ZIP и его контрольная сумма.

Не меняйте набор маркеров `{0}`, `{1}` и т. д. Порядок маркеров можно менять по правилам русского языка. Сохраняйте игровые числа, имена, суммы, обозначения позиций и смысл терминов. Для терминологии ориентируйтесь на [глоссарий](docs/TERMINOLOGY.md).

## Локальные проверки

Нужны Python 3.10+ и Node.js 22+. Внешние библиотеки не требуются. Выполняйте команды из корня репозитория:

```sh
python tools/build.py
node tests/translator.mjs
node tests/templates.mjs
node tests/news.mjs
python tools/verify_package.py
```

Последняя команда сравнивает исходники с **выпущенным** ZIP. После правок словаря расхождение ожидаемо до сборки и проверки нового пакета. Проверка исходников не заменяет проверку игры.

## Сборка установочного пакета

Нужен **свой оригинальный** `app.asar` поддерживаемой сборки — например, созданный установщиком `app.asar.fccd-ru.original`:

```sh
python tools/build.py "D:/SteamLibrary/steamapps/common/Football Coach College Dynasty/resources/app.asar.fccd-ru.original"
```

Готовый пакет будет в `dist/`. Сборщик не изменяет установленную игру. Для неизменённых исходников хеш полученного пропатченного архива совпадает с выпущенной версией. После изменения исходников сборщик обновляет хеши создаваемого пакета; перед распространением его нужно проверить на копии игры.

Не загружайте в репозиторий архивы игры, её исполняемые файлы, базы сохранений и пользовательские профили. Для следующего выпуска обновите версию, манифест, ZIP, контрольную сумму и заметки выпуска.

## Публикация релиза

Workflow `release.yml` проверяет готовый пакет и публикует релиз 0.2.0 при добавлении или обновлении его ZIP или описания в `main`. Его также можно запустить вручную на вкладке Actions. Файлы существующего релиза не перезаписываются; описание можно обновить. При следующем выпуске нужно обновить версию в workflow и связанных файлах.
